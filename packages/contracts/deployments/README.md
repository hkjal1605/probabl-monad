# Deployment manifests

`manifest.schema.json` defines the committed format. Actual manifests are generated by `scripts/deploy-v1.ts` only after successful receipts and must be independently reconciled with the chain before publication.

Never copy an address between networks. Consumers must validate `chainId`, deployment block, runtime bytecode hash, and the immutable dependency graph.

New remediation-era manifests are named `v1-<authority-address>.json`, carry `source`, `deployer`, constructor/deployment evidence, configuration receipts, and `productionApproved: false`. Legacy `v1.json` files are historical evidence only and do not satisfy the new verifier. Preserve them; do not reinterpret them as remediated deployments. Run `verify:v1` with `DEPLOYMENT_MANIFEST` after final admin acceptance, and independently reconcile all role-grant/revoke events before release.
